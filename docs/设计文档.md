## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| GUI | **PySide6 6.11**（Qt6 官方 Python 绑定，LGPL） | 原生桌面体验、自绘 K 线可控、单依赖打包稳定 |
| 网络 | **requests** | 同步简单；配合线程池使用；已验证环境可用 |
| 数据 | 腾讯 `qt.gtimg.cn` / 东方财富 `push2*.eastmoney.com` / 新浪 `hq.sinajs.cn` | go-stock 等 7.4k★ 项目同源使用的免费公开接口，无需 token |
| AI | **自研 OpenAI 协议客户端**（requests + SSE 解析） | 不引第三方 SDK，体积小；天然支持任意 OpenAI 兼容厂商 |
| 存储 | JSON 文件（config + 自选） | 零依赖、可读、可手动备份 |
| 打包 | **PyInstaller 6.22 onefile + windowed** | 产出单文件 exe |
| 测试 | pytest | 指标计算、协议解析、接口字段解析可离线单测 |

Python 版本：3.13（本机 miniconda 环境）。

```
│  MonitorPage 策略监听  BacktestPage 回测                            │

├──────────┬──────────────────────────────┬──────────────┬───────────┤
│ services │           core.ai            │ core.monitor │core.notify│
│ quote/   │  OpenAI客户端 + 厂商注册表    │ 定时全市场扫描│飞书/钉钉/ │
│ screener │  prompt 上下文(信号/回测报告) │ 信号去重     │企微webhook│
├──────────┴───────────────┬──────────────┴──────────────┴───────────┤
│    策略引擎 core.strategy（规则判定，监听与回测共用）                │
├──────────────────────────┴──────────────────────────────────────────┤
│    回测引擎 core.backtest（事件驱动日级撮合，与监听同口径）          │
├─────────────────────────────────────────────────────────────────────┤
│              数据源层 core.providers（注册式）                       │
│  TencentProvider │ EastmoneyProvider │ SinaProvider(备用)           │
└──────────────┬──────────────────────────────────────────────────────┘
               │ HTTPS (requests, 超时/重试/UA/可选代理)
   qt.gtimg.cn │ push2his.eastmoney.com │ push2.eastmoney.com │ ...
```

- **线程模型**：UI 主线程只做渲染；所有网络/计算走 `Worker(QRunnable)` + `QThreadPool`，结果经 `Signal` 回主线程。行情定时刷新由 `QTimer` 触发一次后台拉取，避免重叠（在途时跳过）。
- **数据流（个股诊断）**：`DetailPage` → 并行取 quote + kline + news → `indicators.analyze()` 得指标摘要 → `prompt.build_stock_context()` 拼上下文 → `ai.chat_stream(messages)` → 信号逐块回传 → `QTextBrowser` 渲染。

## 4. 数据源层设计

### 4.1 通用约束
- UA 伪装浏览器；超时 8s；失败重试 2 次（指数退避 0.5s/1s）；全部解析**防御式**：缺字段置 None，绝不让异常冒泡到 UI。
- 编码：腾讯/新浪为 GBK，东财为 UTF-8。

### 4.2 腾讯实时行情（主源）
`GET https://qt.gtimg.cn/q=sh600519,sz000001,...`（GBK），返回 `v_sh600519="1~贵州茅台~600519~价格~昨收~今开~成交量(手)~外盘~内盘~...~时间~涨跌~涨跌幅%~最高~最低~...~换手率~PE~...~振幅~流通市值~总市值~PB~涨停~跌停~量比..."`。

以 `~` 分割取字段（0 基索引）：1 名称、2 代码、3 现价、4 昨收、5 今开、6 成交量(手)、30 时间、31 涨跌额、32 涨跌幅、33 最高、34 最低、38 换手率、39 PE(TTM)、43 振幅、44 流通市值(亿)、45 总市值(亿)、46 PB、47 涨停价、48 跌停价、49 量比。指数无 38 之后字段，按长度截断处理。

代码→市场前缀映射（providers/base.py `to_market_symbol`）：
- `6/9/5` 开头 → `sh`；`0/2/3` → `sz`；`4/8` 及 `92` → `bj`（北交所）。指数：`sh000001` 上证、`sz399001` 深成、`sz399006` 创业板、`sh000688` 科创 50。

### 4.3 东方财富（K 线 / 全市场 / 资讯）
| 用途 | 端点 | 关键参数/字段 |
|---|---|---|
| K线 | `https://push2his.eastmoney.com/api/qt/stock/kline/get` | `secid=1.600519`（沪=1/深=0/北=0）、`klt`=101日/102周/103月、`fqt=1` 前复权、`fields2=f51..f61`；klines 每条 `date,open,close,high,low,volume,amount,振幅,涨跌幅,涨跌额,换手率` |
| 全市场快照 | `https://push2.eastmoney.com/api/qt/clist/get` | `fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23,m:0+t:81+s:2048`、`pz=200` 分页、`fid=f3` 排序；字段 f2 现价 f3 涨跌幅 f5 量 f6 额 f8 换手 f9 PE f10 量比 f12 代码 f14 名称 f15/16 高低 f17 开 f18 昨收 f20 总市值 f21 流通市值 f23 PB f62 主力净额 |
| 7×24快讯 | `https://np-weblist.eastmoney.com/comm/web/getFastNewsList` | `fastColumn=102`，`title/summary/showTime/code_list` |
| 个股公告 | `https://np-anotice-stock.eastmoney.com/api/security/ann` | `stock_list=600519`，返回 `art_title/notice_date/art_code` |
| 个股新闻 | `https://search-api-web.eastmoney.com/search/jsonp` | `type=["cmsArticleWebOld"]`，jsonp 去壳取 `MediaList: title/date/url/content` |

`secid` 规则：沪（6/9/5 开头）→ `1.<code>`；深 → `0.<code>`；北交所 → `0.<code>`。

### 4.4 新浪行情（备用源）
`GET https://hq.sinajs.cn/list=sh600519`（GBK，需 Referer: https://finance.sina.com.cn）`名称,今开,昨收,现价,最高,最低,...,日期,时间`。仅作腾讯失败时的降级与字段补齐。

### 4.5 Provider 注册
`providers/base.py` 维护 `PROVIDERS: dict[name, Provider]`；`Provider` 暴露 `get_quotes(codes) / get_kline(code, period, limit) / get_news(code) / search(keyword)`；上层通过配置选择主源，异常时自动尝试备用源一次。

## 5. 指标引擎（core/indicators.py，纯 Python）

输入 OHLC 数组，输出 `IndicatorSnapshot`（全部 float|None）：

- **MA(n)**：滚动均值（不足 n 天为 None）。
- **EMA(n)**：`ema[i]=α*x+(1-α)*ema[i-1]`，α=2/(n+1)。
- **MACD(12,26,9)**：DIF=EMA12-EMA26；DEA=EMA9(DIF)；MACD柱=2*(DIF-DEA)。状态：DIF 上穿 DEA → 金叉；反之死叉。
- **RSI(n)**（Wilder 平滑）：`RS=avgGain/avgLoss`，RSI=100-100/(1+RS)。>70 超买，<30 超卖。
- **KDJ(9,3,3)**：RSV=(C-Ln)/(Hn-Ln)*100；K=2/3*K'+1/3*RSV；D=2/3*D'+1/3*K；J=3K-2D。J>100 超买，J<0 超卖；K 上穿 D 金叉。
- **BOLL(20,2)**：MID=MA20；UP=MID+2σ；LOW=MID-2σ。
- **形态判定**：多头排列（MA5>MA10>MA20>MA60）、空头排列、金叉/死叉、量能（今日量 vs 5日均量）。

单测用确定性数据断言数值（与标准公式对齐）。

### 6.3 客户端（client.py）

- `chat(messages, stream=True, on_delta=None) -> str`：POST `{base_url}/chat/completions`，body=`{model, messages, stream, temperature, max_tokens}`；流式按行解析 SSE（`data: {...}`，取 `choices[0].delta.content`，`[DONE]` 结束）；非流式取 `choices[0].message.content`。
- 错误分类：连接错误 / 超时 / HTTP 4xx（附响应体提示：401 鉴权、404 路径或模型名）/ 5xx；全部抛 `AiError(带人类可读原因)`。
- `list_models() -> [str]`：GET `/models`。
- `test_connection(cfg) -> (ok, msg)`：先 `/models` 后一次 8 token 的 chat 快测。

### 6.4 上下文与模板（prompt.py）

`build_stock_context(snapshot, indicators, kline_summary, news) -> str`：紧凑文本（现价/涨跌幅/换手/量比/市值/PE/PB + MA/MACD/RSI/KDJ/BOLL 结论 + 近 10 日涨跌概览 + 新闻标题≤8 条）。
模板（system 消息固定角色 + 免责要求）：
- 个股诊断：技术面/资金情绪/消息面/操作参考（含支撑压力位）/风险，分点输出。
- 选股解读：对 TopN 列表逐只一句话点评 + 综合排序建议。
- 新闻解读：事件→对该股可能影响→应对思路。
用户消息 = 模板 + 上下文注入；多轮历史由 AiPage 维护并截断（保留最近 12 条）。

## 7. 选股流水线（core/screener.py）

1. `eastmoney.fetch_all_market(on_progress)`：clist 按 `f6`(成交额) 降序分页 `pz=200`，默认抓前 2000 只（约 10 页，可配"全市场"开关），每页间隔 0.15s，进度回调。
2. 数值过滤（现价/涨跌幅/换手/量比/流通市值/总市值/PE/PB/成交额，勾选才生效）。
3. 技术过滤：对通过筛选的前 `MAX_T_CHECK=120` 只并发拉日 K（线程池 8 并发），算指标，应用"均线多头/MACD金叉/RSI≤70"开关。
4. 按涨跌幅或自定义列排序输出；`ai_comment(top_n)` 生成 AI 点评。

## 8. UI 设计（PySide6）

- 主窗口 `QMainWindow`：左侧 `QListWidget` 导航（行情/选股/AI 分析/资讯/设置）+ `QStackedWidget`；个股详情为独立窗口（`DetailDialog`），深色 QSS 主题。
- **行情页**：顶部指数卡片行（QLabel 网格）→ 搜索栏 → 自选 `QTableWidget`（右键删除、双击开详情）；`QTimer(refresh_sec)` → Worker 拉腾讯行情。
- **详情窗**：头部报价区 + `KLineChart`（自绘：价格蜡烛+MA 线+成交量柱，鼠标移动十字线与 OHLC 浮标，滚轮切换显示根数）+ 指标标签区 + "AI 诊断"按钮（跳转 AiPage 并自动构建上下文）。
- **选股页**：条件表单（QGroupBox 分"价格/资金/估值"）→ 开始按钮（进度条 + 页数日志）→ 结果表 → "AI 点评 Top N"。
- **AI 页**：左侧配置栏（厂商预设下拉、base_url、key(密码框)、model 可编辑下拉 + 获取列表、温度、保存/测试）+ 右侧对话区（`QTextBrowser` 流式追加、底部输入框、模板按钮、多轮开关、清空）。
- **资讯页**：左 7×24 快讯列表（定时刷新），右个股新闻（输代码拉取），均支持"AI 解读"。
- **策略监听页**：左策略管理（内置模板列表 + 自定义策略：名称/买入规则行编辑器[指标-运算符-阈值]/卖出规则/风控参数，保存到配置）；右信号表（时间/代码/名称/策略/现价/止损/目标/风险分/理由），行操作：详情、加入自选、AI解读、标记持仓；顶部开关"自动扫描"+间隔+手动"立即扫描"，底部扫描日志。自动扫描由 QTimer 驱动 Worker 执行 monitor.scan_once。
- **回测页**：策略选择、股票范围（自选/代码列表/成交额TopN）、区间天数、资金、费率、止盈止损/最大持有 → "开始回测"（进度条）→ 绩效摘要卡片（收益/年化/胜率/盈亏比/最大回撤/交易数）+ 逐笔明细表 + "AI 解读回测报告"按钮。
- **设置页**：刷新间隔/K 线根数/主题/代理 + **通知配置**（飞书 webhook、钉钉 webhook+加签密钥、企微 webhook、推送范围、测试按钮）+ **监听配置**（自动扫描开关/间隔/信号保留天数）+ 数据目录打开。
- **设置页**：刷新间隔/K 线根数/主题/代理 + 数据目录打开。
- Worker 框架：`Worker(fn, *args, on_done, on_err, on_progress)` 提交 `QThreadPool.globalInstance()`；UI 信号槽全部跨线程安全（Signal 发射在 worker 线程，Qt 自动排队到主线程）。

## 12. 策略引擎设计（core/strategy.py）

### 12.1 规则 DSL

每条规则 = `{indicator, op, value}`，在**单只股票的指标上下文**上求值：

| indicator（上下文字段） | 含义 | value 示例 |
|---|---|---|
| price / change_pct / turnover_rate / volume_ratio | 快照字段 | 5.0 |
| ma5 / ma10 / ma20 / ma60 | 均线 | 10.0 |
| dif / dea / macd_hist | MACD | 0.0 |
| rsi6 / rsi12 / rsi24 | RSI | 30 |
| k / d / j | KDJ | 20 |
| boll_up / boll_mid / boll_low | 布林 | 12.0 |
| macd_golden / macd_dead / kdj_golden / ma_bull / ma_bear | 布尔形态 | true |
| high_n(20) | 近 N 日最高价（value=N 用 rule.n） | — |
| vol_vs_ma5 | 量/5日均量 | 1.5 |

运算符：`>` `<` `>=` `<=` `==` `between`（value=[a,b]）。任一布尔形态字段直接与 true/false 比较。

### 12.2 数据结构与求值

```python
@dataclass
class Rule:      indicator: str; op: str; value: object; logic: str = "and"
@dataclass
class Strategy:  name; buy_rules: list[Rule]; sell_rules: list[Rule];
                 stop_loss_pct=6.0; take_profit_pct=12.0; max_hold_days=20
```

`eval_rules(rules, ctx) -> (hit: bool, hit_rules: list[str])`：全部 and 规则命中才算触发（规则内可标 or，任一 or 命中即可，需同时满足全部 and）。
`check_signal(strategy, quote, klines, ind) -> Optional[TradeSignal]`：

- TradeSignal：time, code, name, strategy, side(buy/sell), price(=现价, **参考买入成本**), stop_price=max(MA20, 现价×(1-stop_loss_pct%)), target=现价×(1+take_profit_pct%), risk_score(0~100), risk_notes[], hit_rules[], reason 文本。
- 风险评分 = 0.35×偏离MA20百分比归一 + 0.25×近20日振幅(ATR%) + 0.2×RSI6 超买程度 + 0.2×换手率过热，映射到 0~100 并四舍五入；risk_notes 记录扣分项。

### 12.3 内置策略（盈利导向，可复制修改）

| 策略 | 买入规则 | 卖出规则 |
|---|---|---|
| 趋势启动 | ma_bull==true 且 macd_golden==true 且 0<change_pct<6 | 跌破MA20 / 止盈止损 / 20天 |
| 放量突破 | close>=high_n(20) 且 volume_ratio>1.5 且 turnover 3~15 | 跌破MA10 / 止盈止损 / 15天 |
| 回调企稳 | low<=ma20 且 close>ma20 且 ma20 上升(=ma20[i]>ma20[i-3]) 且 volume_ratio<1.2 | 跌破MA20 / 止盈止损 / 20天 |
| 超卖反弹 | rsi6<30 且 close>low(前一日) | rsi6>70 / 止盈止损 / 10天 |

## 13. 监听服务设计（core/monitor.py）

- `MonitorService`（纯 Python，UI 用 QTimer 驱动，无 Qt 依赖，可单测）：
  - `scan_once(strategies, universe, quote_provider, kline_provider, on_progress) -> list[TradeSignal]`
    1. 拉全市场快照（复用 eastmoney.fetch_all_market，默认 Top 2000 成交额）；
    2. **粗筛**：用纯快照规则（量比/换手/涨幅等）把 5000+ 压到 ≤150 只候选；
    3. 对候选并发（8 线程）拉日 K（limit=120）算指标，跑买入规则；
    4. 对"持仓跟踪列表"（买入信号标记 + 用户自选标记持仓）跑卖出规则；
    5. 去重：`fired` 键 = `code|strategy|side|当日`（存配置，跨重启生效）；
    6. 返回新信号列表（UI 展示 + notify 推送）。
- 交易时段判断：`is_trade_time(dt)`（周一~周五 9:25-15:05，节假日不判断，README 说明）；非交易时段自动扫描跳过（手动扫描不受限）。
- 卖出跟踪持仓状态存 `monitor.positions: {code: {entry_price, entry_date, strategy}}`；用户可手动添加/移除。

## 14. 回测引擎设计（core/backtest.py）

- 输入：`BacktestConfig(strategy, codes, days=250, cash=100000, fee_rate=2.5e-4, stamp_tax=5e-4, take_profit_pct, stop_loss_pct, max_hold_days)`。
- 流程：逐股拉日 K（limit=days+60 供指标预热）→ 按日迭代：
  - 无持仓且买入规则当日命中 → 次日开盘价买入（更贴近实盘），仓位=单股全仓（等权）；
  - 持仓中：先判止损/止盈（盘中价触及即按触发价成交）→ 卖出规则收盘命中按收盘卖 → 超过 max_hold_days 次日开盘卖；
  - 费用：买入金额×fee_rate；卖出金额×(fee_rate+stamp_tax)，按 100 股整手取整。
- 输出 `BacktestResult`：start/end、total_return_pct、annual_return_pct（复利年化）、win_rate、profit_factor（Σ盈利/Σ亏损，无亏损为 inf）、max_drawdown_pct（逐日权益曲线）、trades 数、avg_hold_days、equity 曲线点、`trades: list[Trade]`（code、买入日/价、卖出日/价、pnl%、持有天数、原因）。
- 多股并行 ThreadPoolExecutor(8)；全流程纯 Python 可离线单测（合成 K 线）。

## 15. 消息通知设计（core/notify.py）

| 通道 | 端点 | payload |
|---|---|---|
| 飞书 | `POST https://open.feishu.cn/open-apis/bot/v2/hook/{token}` | `{"msg_type":"text","content":{"text":"..."}}` |

## 27. AI 调用健壮性（v1.6）

### 27.1 重试机制（core/ai/client.py）

- `chat` 拆为 `_post_chat`（可重试的请求阶段）与 `_read_response`（读流阶段）。
- 请求阶段：`AiError(retryable)` 标记；`RETRY_STATUSES=(429,500,502,503,504)` + 网络错误，退避 1.5/3.0/6.0s 共 3 次重试后抛出。鉴权/路径类（401/403/404）立即抛出不重试。
- 读流阶段不重试：SSE 已开始输出再中断重试会导致内容重复；由用户点「重新分析」。
- `friendly_error(status, body)`：错误分类中文化 + `retryable` 判定 + 原文截断附注（≤400 字符）。
- `test_connection`：轻量真实对话（max_tokens=16）；`retryable` → "服务暂时繁忙（可自动重试）"，否则 "不可用"。

### 27.2 报告区呈现（ui/ai_stream.py）

- `append_stream(view, kind, text, raw=False)` 新增 `user`（聊天气泡：蓝底圆角）与 `system`（灰色小字提示，raw 直插）与升级版 `error`（红边卡片、含原文附注、不重复）。
- Worker 错误信号对 `AiError` 去掉异常类名前缀（workers.py）。
- 单测（tests/test_ai_retry.py）：503 两次后成功恢复、401 立即抛、重试上限后抛 retryable、friendly_error 文案断言。

### 28.2 对话结构（append_stream kind 扩展）

- `user`：蓝底圆角气泡（🧑 前缀由组件统一添加，调用方不再传）

## 31. 中文编码乱码根治（v2.0）

### 31.1 根因

AI 流式（SSE）原实现 `resp.iter_lines(decode_unicode=True)`：requests 在响应头 `Content-Type: text/event-stream`（无 charset）时按 RFC 默认 **ISO-8859-1** 解码 UTF-8 字节流 → 每个中文成 2~3 个 latin-1 字符（`达` → `è¾¾`），即用户报告的乱码。本地 mock 测试曾出现同样现象（当时被误判为"UTF-8 字节切分"问题）。

### 31.2 修复（三处 + 一处防御）

| 位置 | 修复 |
|---|---|
| `ai/client.py::_read_response` | `iter_lines(decode_unicode=False)` 按字节读行 → `raw.decode("utf-8")`；坏块（多字节跨 chunk）`errors="ignore"` |
| `ai/client.py::_resp_text_utf8` | 错误响应体（chat/models 的 4xx/5xx）强制 UTF-8 解码（GBK 次选），供 friendly_error 展示服务方原文 |
| `notify.py::_post` | webhook 错误体 `r.content.decode("utf-8", errors="replace")` |
| `providers/base.py::get_text` | 防御：无显式 encoding 时，响应头 charset 缺失/为 latin-1 → `apparent_encoding` 探测，兜底 UTF-8（腾讯/新浪 GBK 调用点不受影响——仍走显式 encoding 分支） |

### 31.3 全链路排查结论（其余无乱码风险）

- 腾讯行情/K线、新浪行情/板块：`get_text(encoding="gbk")` 显式 GBK ✅
- 东财 JSON 接口：`resp.json()` 按 JSON RFC 自动 UTF-8 ✅
- CSV 导出：`utf-8-sig`（BOM）✅；配置/日志读写显式 `encoding="utf-8"` ✅
- 通知正文：纯内存 str ✅

### 31.4 验证

- 单测（test_encoding_fix.py）：无 charset SSE 中文正常 + 无 `è/å` 乱码特征；503 错误体中文原文正常。
- 端到端：无 charset mock 服务，多字节中文跨 chunk、两轮对话 —— 报告区全文中文，断言 PASS。
- 回归：71 个测试全部通过（test_ai_retry 桩同步改为 bytes 行）。

## 45. v4.4.2 性能优化：并行分页 + 主机熔断（2026-09-06）

- 按 host 隔离（push2 熔断不拖累 datacenter/新浪）。

## 46. v4.4.3 机会分析优化：并行/去重/缓存 + 两项链路修复（2026-09-06）

用户诉求：拉取数据后并行分析、重复数据不重复处理、使用缓存机制。剖开后先撞出一个**比优化更严重的老 bug**，先修后优。

### 46.1 kline_for_scan 签名错配（机会扫描全灭的根因）

monitor.py 调 `kline_fetch(code, "day", 800)`，但 `kline_for_scan` 形参是 `(code, limit, max_age_days)`——**`"day"` 被当 limit 绑进 SQLite `LIMIT ?` → IntegrityError: datatype mismatch**，check_row 全部吞异常返回空 → 机会雷达 0.02s 出 0 信号（快是假象，实际什么都没分析）。修复：签名 `(code, limit=None, max_age_days=4)` + 内部归一，兼容 `(code,limit)`/`(code,"day",800)`/`(code)` 三种历史口径。修复后 99 信号回归。

教训：吞异常的 `except: return []` 掩盖了签名错配整条链路的静默失效——DEBUG 日志一开 300 行"datatype mismatch"立刻现形。

### 46.2 三项优化（用户要求的三件事）

| 优化 | 实现 | 实测 |
|---|---|---|
| 并行分析 | check_row 池 8→12 workers（I/O+CPU 混合负载） | 全市场扫描 2.2s |

1. **盘中监测 Agent** 的规则集（价格异动/技术信号/量能/风控线/超买卖）与"AI 判断是否值得提醒"的两段式；
2. **ATR 自适应异动阈值** `max(固定阈值, 1.5×ATR%)`——高波动股 ±5% 是常态不误报、低波动股 ±3% 已是异动不漏报；
3. **通知节流**：同股同类型 30 分钟内不重复；
4. 风控线直接以**用户持仓成本为锚**（止损/止盈从成本推算），策略关联参数优先。

**不采用的**：PanWatch 全 AI 判定提醒（每轮每股一次 LLM 调用，桌面单机成本高）——改为**规则先行、AI 可选**：确定性规则零成本实时跑，AI 解读按钮按需触发。

### 56.5 v7.2 错误呈现规范（用户要求：异常弹窗报错，不进页面布局）

用户痛点：异常文本（长串 ProviderError）直接 setText 到主布局控件（价格标签/进度区/标题区），页面布局被打乱。

**规范**（ui/err.py 统一助手，9 处错误点全改造）：
